# Centralizator RCA — ghid pentru Claude

Aplicație pentru gestionarea dosarelor RCA (mașini de înlocuire). Limba interfeței și a conversației: **română**.
Live: https://patcas97pxb.github.io/centralizator-rca/ · Repo: `Patcas97PxB/centralizator-rca` (ramura `main`).

## Structura repo-ului
- `app/` — aplicația nouă: Vite + React 19 + TypeScript, Tailwind v4 (config în `app/src/index.css`), shadcn/ui, lucide-react. **Aici se lucrează.**
- **Rădăcina repo-ului (`index.html`, `assets/`) = build-ul publicat.** GitHub Pages servește rădăcina, nu `app/`.
- `icons/`, `js/`, `shared/` — resurse folosite și de app (Vite le servește/copiază, vezi `app/vite.config.ts`). **`js/extractie.js` se modifică, apoi se copiază în `shared/extractie.js`** (rădăcina `shared/` e ce servește site-ul live). În `index.html` build-ul adaugă `?v=<hash conținut>` la aceste scripturi, ca browserul să nu rămână cu versiunea veche din cache.
- `supabase/` — migrări. Datele stau în Supabase (tabelul `dosare`, coloana `data` jsonb; câmpuri noi opționale nu cer migrare).
- `File/` — **în .gitignore** (documente interne, grile asiguratori, poze mașini). Nu ajunge pe GitHub.
- `Centralizator RCA - site.html` — mockup-ul de design (netrack-uit). Sursa adevărului pentru aspect. Varianta „standalone" era greșită și a fost eliminată.

## Comenzi (din `app/`)
- Typecheck: `npx tsc --noEmit -p tsconfig.app.json`
- Build: `npm run build`
- Dev: în Claude Code, `preview_start` cu `rca-app-nou` (port 5180, vezi `.claude/launch.json`); `rca-site` (5175) servește mockup-ul.
- Aplicația cere **email Autonom + parolă** la intrare. **Nu introduce parola** — cere utilizatorului să se logheze în panoul Browser.

## Publicare pe live (IMPORTANT — nu ajunge un simplu push)
1. `cd app && npm run build`
2. Din rădăcină: `git rm -rq assets && cp -r app/dist/assets assets && cp app/dist/index.html index.html && rm -rf ocr-models && cp -r app/dist/ocr-models ocr-models && git add assets index.html ocr-models` (modelele PaddleOCR din `ocr-models/` trebuie să fie și ele în rădăcină)
3. `git commit` + `git push origin main`
4. Așteaptă „pages build and deployment" (`gh run list --limit 1`), apoi verifică asset-urile noi (curl 200).
**Adresa de test** (înainte de publicare, când utilizatorul vrea să verifice): `cd app && npx vite build --base=/centralizator-rca/preview/ --outDir dist-preview --emptyOutDir`, apoi din rădăcină `rm -rf preview && cp -r app/dist-preview preview && rm -rf app/dist-preview`, commit + push pe `main` → https://patcas97pxb.github.io/centralizator-rca/preview/ (site-ul principal neschimbat; aceeași bază de date).
**Varianta de test pentru alții** (`/demo/`, parola „DEMO”, fără diferență între litere mari/mici; sus în dreapta apare „DEMO” în loc de nume): build cu `VITE_DEMO=1` (`lib/demo.ts`). Nu atinge Supabase: dosarele vin din `date-demo.enc` (backup-ul utilizatorului criptat AES-GCM cu parola, `node scripts/cripteaza-demo.mjs <backup.json> DEMO <ieșire>`), iar modificările testerului stau doar în IndexedDB-ul browserului lui (banner „VARIANTĂ DE TEST” + „Resetează datele”). Documentele originale nu sunt incluse. Protecție anti-copiere doar descurajantă (`lib/demo-protectie.ts`). Publicare: `cd app && VITE_DEMO=1 npx vite build --base=/centralizator-rca/demo/ --outDir dist-demo --emptyOutDir && node scripts/cripteaza-demo.mjs <backup> DEMO dist-demo/date-demo.enc`, apoi `rm -rf demo && cp -r app/dist-demo demo`. **Nu comite niciodată backup-ul necriptat.**
Comite local oricând, dar **push doar când cere utilizatorul**. Pozele de mașini ajung pe site doar prin acest build local.

## Reguli de business stabilite
- **Culoarea cardului = termenul**, nu statusul: roșu ≤0 zile/expirat, galben 1–2, verde ≥3, albastru programare (înainte de predare), gri finalizat. Pastila de status păstrează culoarea statusului (`STATUS_META`). Implementare: `prioritateDosar`/`urgentaDosar` în `lib/rca-calc.ts`.
- **Ordinea cardurilor**: roșu → galben → verde → albastru → finalizate jos. Un dosar tocmai finalizat rămâne pe loc ~2,5 s (animația de finalizare), apoi coboară cu animație de mutare (`DosarePage.tsx`).
- **Clopoțel (`dosareDeSunat`)**: intră dosarele cu status `de_sunat` (manual) sau cu ≤2 zile până la termen (inclusiv expirate). Se sting la `in_asteptare`, `astept_docum`, `finalizat`. Click pe un dosar din listă te duce la cardul lui. La fel în **Activitate recentă** (panoul din dreapta): click pe rând → scoate filtrele, derulează la card și îl evidențiază (`lib/mergi-la-dosar.ts`).
- **Finalizarea e blocată** dacă lipsesc documente obligatorii (`lipsuriFinalizare`, `lib/documente.ts`). 9 tipuri numărate; „RCA vinovat/păgubit" sunt incluse în „Documente vinovat/păgubit"; **Contract final** = cheia `contract`, mereu obligatoriu. Etichetele vechi `rca_*` se normalizează la citire (`types.ts`).
- **Contract final**: se încarcă din modalul de documente sau din „Editează". `lib/contract-final-import.ts` verifică să fie al dosarului și completează zile, valoare (cu/fără TVA), clasă etc. Un fișier greșit e respins fără să încarce nimic. Acceptă și **scanări/poze**: PDF fără text sau imagine → OCR Tesseract (`textContract`); regex-urile din `contract-final.ts` tolerează greșeli OCR („și”, „;”, „R8H”, „14,09.2026”). La scan: nr. auto/contract/dosar se compară tolerant (≤2 caractere diferite, `aproapeLaFel`), nr. auto păgubit care nu arată a nr. RO e ignorat, rândul de cost se ia doar de pe linia lui (sume fără virgulă → ultimele 2 cifre = zecimale; „Total: X EUR” are prioritate). Nr. dosar poate conține cratime; la **Hellas** formatul canonic e „HDR 121926” — sufixul „-4698” de pe contract se taie (ca în `shared/extractie.js`), și la comparație (`normDosar`). La **Generali** dosarul are sufix de ordine („202650518271-R/1”), iar pe contract apare fără el („202650518271R”) — `acelasiDosar` le consideră egale (scoate un „/cifre” final doar la comparația cu contractul; la duplicate „-R/1” ≠ „-R/2”). Nr. rezervare se compară doar pe cifre („RBH/29770” = „RBH 29770” = „29770”). Toleranța OCR acceptă doar confuzii reale (8↔B↔S, 0↔O, 1↔I…), nu orice cifră. Testat în browser pe scanul real CONTRACT_BH88PMP (Hellas, RBH/29770, 4 zile, 128,00/154,88 EUR) — ~8 s.
- **Înainte de predare** (bifa Predat nepusă, data predării azi/viitor): cardul albastru arată „X zile până la predare” sau „AZI · predare AZI”; zilele de termen apar abia după bifa Predat. Data predării trecută fără bifă (ex. dosare vechi) → zilele normale.
- **MAJUSCULE**: la creare/editare, câmpurile scrise (nr. dosar, nr. rezervare, nr. auto păgubit/înlocuire, marcă/model, note) se salvează cu litere mari de tipar, și când vin din PRELUARE DATE/contract (`lib/majuscule.ts`, folosit în `DosarFormModal` și `DocumenteModal`). Câmpurile alese din listă (asigurator, status, vehicul, clasă, service) rămân ca în listă. Dosarele vechi se convertesc când le deschizi și salvezi.
- **Predat / Preluat** pe card: bife (`predatBifat`/`preluatBifat`), fără efect pe status. Preluat se poate bifa doar după Predat. **Preluat bifat** = mașina e returnată, mai trebuie închis contractul: cardul devine verde („zile · preluată, închide contractul”), fără „peste termen”, nu intră la Depășite și iese din clopoțel (dacă nu e marcat manual `de_sunat`).
- **Poza cardului = vehiculul de înlocuire** (`marcaModelInlocuire`), nu mașina păgubită. Pozele se iau din `File/Cars/car_nobg` (`lib/cars.ts`, potrivire pe cuvinte: „Arkana" = „Renault Arkana"). Poză nouă în folder → repornește serverul de dev.
- **Statistici** (panoul din dreapta): total/finalizate/în curs, service și asigurator cu cele mai multe dosare, vehiculul de înlocuire cel mai oferit (cu poză).
- **Moneda (Rapoarte)**: contractele **Allianz sunt în lei**, ale celorlalți asiguratori în **EUR** (`monedaDosar`, `lib/financiar.ts`; fără câmp nou). Rândurile arată moneda lor, subtotalurile și TOTAL GENERAL sunt separate („261,50 EUR + 4.375,00 lei”), exportul CSV/XLSX are coloana Monedă. Sumele se citesc cu `parseSuma` („4.375.00”, „4 375,00”, „133,50” — înainte „4.375.00” ieșea 0). Allianz: valoarea se compară cu grila în lei, intern **sau** extern (`totalExtern`); altfel „⚠️ TARIF DE VERIFICAT”.
- **Căutare în Rapoarte** (câmpul „Caută” din bara de filtre, `corespundeCautarii` în `lib/financiar.ts`): ca la Dosare — nr. auto (și „BH 89 TAX”), RBH, nr. dosar, asigurator, service, clasă, marcă și **sumă** („4375”, „4.375,00”, „154.88”). Se combină cu perioada/service-ul; totalurile și exportul CSV/Excel urmează rezultatele.
- **Dosar duplicat**: la Salvează în formular, dacă alt dosar are același nr. (`normDosar`: fără spații/cratime, sufixul Hellas), apare „Există deja dosarul X … Salvezi totuși?” (Anulează / Salvează oricum) — avertizare, nu blocare.
- **Josul paginii** (`components/layout/SiteFooter.tsx`, și pe ecranul de parolă): „© an Pătcaș Bogdan · Centralizator RCA. Toate drepturile rezervate.” + linkuri Confidențialitate (GDPR) / Termeni și condiții / Cookie-uri, deschise în fereastră. Textele sunt în `legal-texte.tsx` (model standard, titular = Pătcaș Bogdan, fără email public; în demo apar mențiuni despre datele de test). Textele **nu numesc furnizorii** (Supabase, GitHub, CDN-uri) — doar „furnizori specializați de infrastructură cloud”, „rețele publice de distribuție” (cerința utilizatorului). De verificat de un jurist.
- Legenda culorilor e în butonul „i" din rândul de filtre. Dashboard/Setări = „în curând".
- **Modificare PDF** (cardul din dreapta): editor în browser, fără API/AI/server. `lib/pdf-editor.ts` + `ModificarPdfModal.tsx`. MuPDF.js (WASM, licență AGPL, încărcat lazy) citește cuvintele cu poziții și **șterge definitiv** textul ales; pdf-lib scrie noul text în același loc (font, mărime și culoare din original; Arimo ca rezervă pentru ș/ț/ă). **Nuanța se potrivește vizual** (`tonZona`): se măsoară cât de închis arată originalul randat și, dacă textul nou iese mai apăsat (transparență pierdută, font mai gros), culoarea se deschide până la același ton — doar deschide, nu intunecă. După ștergere verifică să nu se fi schimbat altceva, altfel refuză. **Rânduri dese** (PV cu font mic): dreptunghiul complet al cuvântului atinge literele rândului de sus/jos — atunci se reîncearcă automat cu dreptunghiul îngustat la miezul literelor (`miezRect`, în jurul liniei de bază), apoi cuvânt cu cuvânt; eroarea apare doar dacă toate trei ating alt text. Originalul nu se modifică; ieșirea e o copie descărcată + jurnal .txt. Doar PDF-uri cu text (nu scanate). Testat pe „PV PREDARE-PRELUARE + CONTRACT" (Helvetica 7pt). **Separă pagini** (în același modal, la PDF-uri cu 2+ pagini): bifezi numerele paginilor → „Salvează … ca PDF nou” descarcă un PDF doar cu ele (`extragePagini`, pdf-lib; pleacă de la versiunea curentă, cu modificări; merge și pe scanate).
- Instrucțiuni libere pentru PDF („schimbă data…") ar cere Claude API ca interpret, printr-o Supabase Edge Function (cheia din Anthropic Console pusă ca secret în Supabase — niciodată în cod sau în chat). Nu există încă.

- **Zile din deviz** (`lib/deviz-analiza.ts`): (ore manoperă + ore vopsitorie) ÷ 4, rotunjit. Audatex: din „BAZA MANOPERA” + „TOTAL CL”. **GT Estimate**: din sumar — „Total exc. reducere (X h)” (manoperă, cu tot cu întocmire deviz/reconstatare) + „Subtotal Manoperă (Y h)” (vopsitorie). Verificat pe 2 devize GT reale: 30,30 h → 8 zile, 11,50 h → 3 zile. Merge și din poză (OCR Tesseract): trebuie pozată pagina cu totalurile; regex-ul tolerează punct în loc de virgulă, „h” lipsă, paranteze citite greșit. **Audatex fotografiat** (`analizaAudatexPoza`): etichetele ies adesea ilizibile, așa că se iau rândurile „X ORE × preț RON/ORA = sumă” verificate aritmetic (fără cele din Costuri suplimentare) + „TOTAL VOPSITORIE 1 ORA : Y ORE”. Testat pe poza reală DEVIZ_NOU1 BH52LCA (22,0 + 7,7 = 29,7 h → 7 zile), ~45 s pentru 5 pagini. **Mai multe fișiere odată**: „Zile din deviz”, „Calculează zile din deviz” și PRELUARE DATE au `multiple` — se pot alege toate pozele/paginile devizului; `textDinFisiere` (`lib/pdf-ocr.ts`) lipește textul tuturor (PDF text/scanat + poze) și arată progresul „Citesc poza X din N”. Testat: 5 poze BH52LCA alese odată → 7 zile în ~37 s. **Poze de pe monitor / scanări slabe** (ex. DEVIZ - BH42GZS.pdf: Audatex pozat de pe ecran, pus pe A4): dacă prima citire OCR nu găsește orele, `citesteDeviz` (`lib/pdf-ocr.ts`) recitește cu imaginile curățate (`pregatestePentruOcr`: gri, tăiat marginile albe, fundal normalizat, estompare ușoară anti-moiré) — doar ca a doua încercare, pe pozele bune curățarea strică citirea. Rândul de manoperă se acceptă și dacă se verifică cu prețul orei citit în altă parte (OCR 250→350); vopsitoria tolerează „VORSITORIE”, „|”, „ORAL”. BH42GZS → 12,0 + 7,5 = 19,5 h → 5 zile (~65 s). Dacă OCR-ul prinde manopera dar nu orele de vopsitorie, se calculează din cost (1875 ÷ 250 = 7,5 h; doar rezultat cu o zecimală); dacă nici așa → `incomplet` → a doua citire, iar dacă rămâne incomplet cardul arată „Vopsitoria nu s-a putut citi — verifică” (pe live, utilizatorului i-a dat 3 zile = doar manopera, înainte de această regulă).

## PRELUARE DATE (citire NC/PV/deviz)
- Traseu: `lib/citeste-document.ts` (`citesteDocument`). PDF cu text → direct. Poze / PDF scanat → **PaddleOCR în browser** (`lib/paddle-ocr.ts`: `esearch-ocr` + `onnxruntime-web`, modele PP-OCRv4 în `app/public/ocr-models/`, ~16 MB, descărcate la prima folosire) **doar dacă există WebGPU** (`navigator.gpu`); fără placă video sau la eroare → Tesseract ca înainte. Pe procesor (WASM) Paddle era inutilizabil (>2 min/poză). PDF scanat randat la ~200 DPI (scale 2,75) pentru Paddle — la 144 DPI se pierdea „CJ/” la Allianz; Tesseract rămâne la 4.
- **Devize**: dacă textul pare deviz (`manoper|vopsitor|audatex|gt estimate|total cl`), Paddle se oprește după prima pagină și zilele se calculează cu Tesseract (`citesteDeviz`), ca înainte — regulile de devize sunt reglate pe textul Tesseract. Câmpurile lipsă se completează din textul Tesseract. **Netestat pe devize reale** (nu există în `File/`).
- Test comparativ pe 26 NC-uri reale (`File/Invatare/NC`): Tesseract 39/47 câmpuri corecte pe poze/scanări, PaddleOCR + reguli noi ~47/47. Tesseract greșea în citire (BH89SZI, nr. dosar/auto necitite, Grawe ilizibil) — nereparabil din reguli. ~8–18 s/poză, PDF scanat 2–3 pagini ~30–60 s.
- `js-clipper` (dependență Paddle) are comentarii Latin-1: `vite.config.ts` îl citește cu pluginul `clipperLatin1` (și în `optimizeDeps.rolldownOptions`). Dacă Vite dă „Failed to fetch dynamically imported module …/.vite/deps/…” după instalări/dezinstalări: oprește serverul, `rm -rf app/node_modules/.vite`, pornește din nou.
- Reguli noi în `js/extractie.js`: Generali `BH/20261950354-C`; Allianz nr. dosar în căsuțe → `CJ/CR988911` (și „BU /ZB774639” pe rândul de deasupra); Grawe „Seria: BH.10-…” → `BH-10-00-…`; `HDR` lipit („DAUNEHDR122920”); nr. auto **fără cratime** („B83ATM”, confirmat de utilizator) și reparat după poziție doar lângă eticheta „Nr. înmatriculare” (O↔0, S↔5, coduri de județ valide); marcă lipită („SKODAOCTAVIA”, „MeganeIVB9”); marcă greșită de OCR urmată de model cunoscut („Dada Logan” → Dacia). Modelele se caută de la cel mai lung (GLS înainte de GL).
- Exemplele din `tests/fixtures/extractie-camp.json` sunt **anonimizate** (nume, CNP, telefoane, emailuri, VIN → XXXX). Repo-ul e public: nu adăuga text brut cu date personale.

UI: butonul cu ceas din antet = „Recuperare" (`RecuperareModal.tsx`). **Migrarea trebuie rulată și pe baza de pe live înainte de publicare** (altfel „Recuperare" dă eroare, iar textele despre recuperare nu sunt adevărate).

Formularul oferă „Salvează oricum"; acțiunile rapide (`salveazaRapid`) arată banda roșie și reîncarcă. Lista se reîmprospătează la revenirea în filă.
- **Backup**: butonul „Exportă backup” din antet strălucește (inel albastru + pulsație, clasa `backup-glow`) dacă au trecut ≥3 zile de la ultimul export din acest browser sau nu s-a făcut niciunul (`zileDeLaBackup`, localStorage `rca-ultim-backup`). Fără bandă/mesaj — utilizatorul nu vrea. Backup-ul JSON nu conține documentele din storage.
- **Dosar nou cu predare viitoare** → status `de_predat` automat (`cuStatusImplicit` în `DosarFormModal`).

## Capcane cunoscute
- Comenzile bash cu heredoc lung eșuează uneori: scrie scripturile cu `Write` (în scratchpad) și rulează-le.
- Serverul de dev și site-ul live folosesc **aceeași bază de date Supabase**: la teste nu salva/șterge dosare reale (deschide formulare și închide cu Anulează).
- Avertismentele Git „LF will be replaced by CRLF" sunt inofensive.
- **Sesiune în cloud (claude.ai/code)**: nu există panoul Browser și site-ul live (github.io) nu se poate deschide. Verificarea vizuală se face pe build-ul **demo** (parola DEMO, date în IndexedDB, nu atinge Supabase): `VITE_DEMO=1 npx vite build --base=/centralizator-rca/demo/ --outDir dist-demo`, copiezi `demo/date-demo.enc` în `dist-demo/`, `npx vite preview --outDir dist-demo --base=/centralizator-rca/demo/ --port 5199`, apoi Playwright cu `executablePath: '/opt/pw-browsers/chromium'`; capturile se trimit utilizatorului. Pentru OCR/PDF în teste, CDN-urile sunt blocate: pdf.js, Tesseract și datele de limbă (npm `@tesseract.js-data`) se copiază temporar în `app/public/tmp-vendor` și se șterg după. Pozele noi de mașini trebuie trimise în chat (folderul `File/` de pe PC nu e vizibil). Deploy-ul se verifică prin GitHub Actions („pages build and deployment”).
- Modalul de documente salvează automat fiecare schimbare.
- Netestat cu fișiere reale: extragerea zilelor dintr-un deviz Audatex real și citirea unui contract final real (codul e portat din versiunea veche).

## Preferințe de lucru ale utilizatorului
Răspunsuri scurte, în română. Verifică vizual în browser înainte să spui că e gata. Când nu ești sigur de o regulă de business, întreabă. Nu adăuga butoane sau elemente noi pe card fără cerere explicită.
